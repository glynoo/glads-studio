# 四个入口页的第二步实现

依据：PRP 论文第 4.3、4.4、4.6、4.7 节，既有《GLADS Restore V1：五页工作台设计说明》，以及 GLADS v1.0 交付包的 `system_design/`。旧线框中的案例数、洞窟位置、运行状态和模型哈希只是示意，不能当作现有数据。

## 当前可用的事实

本地服务只有 Golden20 参考案例、原图、精确掩码、58 张 Big-LaMa 参考候选，以及本机保存的定位批注和人工复核事件。没有经核验的“项目—洞窟—壁画—区域”索引、学生修复权重、任务运行器、账号权限或正式二级审批服务。

## 页面职责

| 页面 | 这一步可操作的内容 | 明确保留的边界 |
| --- | --- | --- |
| 首页 | 按真实数据统计待复核、已记录判断、风险案例与候选数量；显示优先处理队列和最近判断，直达对应案例。 | 不虚构 GPU、训练、运行中任务或个人分配。 |
| 素材池 | 按案例和资产类型查找原图、精确掩码、参考候选，查看来源与候选 SHA，进入工作台。 | 没有真实洞窟索引时不显示假树；不把参考候选当作正式模型结果。 |
| 审核 | 对已保存的人工判断进行筛选、查看理由与历史，定位到工作台并导出记录。 | 这里是复核记录总览；没有独立审核人、通过/退回或正式归档状态。 |
| 设置 | 显示本地服务与数据源状态、模型接入边界；保存当前浏览器的比较视图偏好。 | 不展示可写的模型参数、权限、任务运行配置。 |

四页只通过 `reviewApi` 读取服务数据。页面使用独立组件和专属 CSS 类，保持工作台数据结构与持久化方式不变。跨页链接使用稳定的 `case_id`，不依靠列表位置。加载、空数据和服务不可用都显示明确状态。人工结论仍只在工作台写入，资产页只读，导出不会更改复核状态。

验收关注真实闭环：首页待办或素材条目 → 指定案例工作台 → 保存复核 → 审核页看到同一记录 → 导出；设置中的偏好在工作台生效。另需在桌面和窄屏检查四页，验证筛选、缺失 R12 与服务故障状态。
